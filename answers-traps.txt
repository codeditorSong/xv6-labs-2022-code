RISC-V Assembly 问答

Q1: 哪些寄存器包含函数参数？例如，在 main 调用 printf 时，哪个寄存器保存了 13？

答：在 RISC-V 调用约定中，函数参数通过寄存器 a0-a7 传递。在 main 对 printf 的调用中：
  - a0 保存格式字符串 "%d %d\n" 的地址
  - a1 保存 f(8)+1 的值（即 12）
  - a2 保存 13
因此，13 保存在 a2 寄存器中。
（从 call.asm 第 45 行可以看到：li a2,13）

Q2: main 的汇编代码中，对函数 f 的调用在哪里？对 g 的调用在哪里？（提示：编译器可能内联函数）

答：在 main 的汇编代码中，没有对 f 或 g 的 jal/jalr 调用指令。编译器将 f(8) 和 g(8) 完全内联并进行了常量折叠：
  - g(x) 返回 x+3，所以 g(8) = 11
  - f(x) 返回 g(x)，所以 f(8) = 11
  - f(8)+1 = 12
在汇编代码中，12 被直接作为立即数加载（第 46 行：li a1,12），因此 f 和 g 都没有实际被调用。

Q3: printf 函数位于哪个地址？

答：printf 函数位于地址 0x630。
（从 call.asm 第 1078 行可以看到：0000000000000630 <printf>:）

Q4: 在 main 中执行 jalr 跳转到 printf 之后，寄存器 ra 中的值是什么？

答：jalr 指令将返回地址（PC+4）保存到 ra 寄存器中。在 main 中：
  - 第 34 行：jalr 1536(ra) # 630 <printf>（位于地址 0x30）
  - 返回地址 = 0x30 + 4 = 0x34
因此，ra 中的值为 0x34。

Q5: 运行以下代码，输出是什么？
    unsigned int i = 0x00646c72;
    printf("H%x Wo%s", 57616, &i);

答：输出为 "HE110 World"。
分析：
  - 57616 的十六进制表示为 0xE110，所以 %x 输出 "E110"
  - i = 0x00646c72 在 little-endian 架构下，内存中的字节顺序为：0x72, 0x6c, 0x64, 0x00
    对应的 ASCII 字符为：0x72='r', 0x6c='l', 0x64='d', 0x00=字符串结束符
    所以 %s 输出 "rld"
  - 完整输出：HE110 World

Q6: 如果 RISC-V 是 big-endian 架构，为了得到相同的输出，i 应该设置为什么值？57616 需要更改吗？

答：如果 RISC-V 是 big-endian 架构：
  - 为了得到相同的字符串 "rld"，内存中的字节顺序需要是 0x72, 0x6c, 0x64, 0x00
    在 big-endian 下，i = 0x726c6400
  - 57616 不需要更改，因为整数 57616 的值在不同字节序下是相同的，%x 会输出相同的十六进制表示 "E110"

Q7: 以下代码中，'y=' 之后会打印什么？（注意：答案不是具体的值）为什么会这样？
    printf("x=%d y=%d", 3);

答：'y=' 之后会打印一个不确定的值（垃圾值/任意值）。
原因：printf 期望两个整数参数（对应两个 %d），但只提供了一个参数 3。第二个 %d 会从 a2 寄存器中读取值，而 a2 寄存器在调用 printf 时没有被初始化，因此包含的是之前某个操作留下的任意值。在 RISC-V 调用约定中，a2 是第三个参数寄存器（第一个参数用 a0，第二个用 a1），所以 printf 会读取 a2 中的任意值作为第二个参数打印。
